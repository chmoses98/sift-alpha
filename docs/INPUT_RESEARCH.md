# Input research: what predicts each Kalshi market, how much, and does it beat the price

**Status: RESEARCH_ONLY.** No orders, no credentials, no paid services. Nothing here is a betting claim. Added on top of (not beside) the existing registry, verification engine and dashboard.

## What it is

| Layer | File | Role |
|---|---|---|
| Candidate inputs | `research/input_research/catalog/<SPORT>.json` (validated by `alpha_engine/input_research/catalog.py`) | For all 8 sports: every candidate predictive input with mechanism, rationale, measurement, pregame-knowability, free sources, and registry link; per blueprint **and** per market archetype (e.g. `qb_passing_yards`, `pitcher_strikeouts`, `player_assists`) the relevant inputs with a market-specific "why" and hypothesised interactions. A hypothesis list, not evidence. |
| Availability audit | `publish.availability()` joined to `research/audit/verification/*.json` | Collection status, point-in-time status, current-model use. Only an **exact** registry-id match inherits registry status; new candidates are `NOT_IN_REGISTRY` and related registry inputs are shown as context only. |
| Statistics | `alpha_engine/input_research/stats.py` | Walk-forward by season, week-cluster bootstrap, Holm (confirmatory) + Benjamini–Hochberg (discovery) control, de-vig, calibration. Self-tested on planted signal / pure noise / outcome-corruption. |
| NFL paths | `nfl_features.py`, `nfl_game.py`, `qb_passing.py` | Point-in-time features from free nflverse data; game total / spread / moneyline vs the closing market; QB passing yards vs the QB's own history. |
| Publish + queue | `publish.py`, `queue.py`, `refresh.py` | `research/audit/input_research/{index,sport_*,queue,run_log,provenance}.json` for the dashboard. |
| Dashboard | `src/input-research.jsx` | Pick sport → market family (→ archetype) and see inputs, rationale, availability, model use, evidence, performance vs benchmark, gaps, queue. |

## Evidence ladder (a family sits at the highest rung actually achieved)

L0 inventory only → L1 tested vs a no-market baseline → L2 tested vs a contemporaneous near-close line → L3 tested vs timestamped Kalshi executable prices incl. spread/fees/depth → L4 pre-registered forward confirmation. **Today: no family is above L2; 4 NFL paths are tested; 271 families are L0.** A "DEMONSTRATED_INCREMENTAL" verdict requires Holm-adjusted p < 0.05, both chronological halves > 0, every leave-one-season-out > 0 and a season-block bootstrap CI > 0 — and still means only "predictive information beyond the stated benchmark", never an after-fee edge.

## What was actually validated (nflverse 2013–2026, test seasons 2017–2026, 2026 games to date included as a forward slice)

Benchmark for L2 = the nflverse schedule-file consensus line / de-vigged price: documented only as a **near-close** sportsbook line (exact timestamp undocumented), **not a Kalshi price**; no spread, fees or depth; the over/under and spread prices are coarse. **Headline models use only strictly pregame-knowable inputs.** The realised starting QB and the observed weather/roof state are only partially knowable before the decision, so they are tested individually and in a labelled sensitivity model but excluded from every headline.

* **NFL game total, spread and winner vs the near-close line: no input, group or interaction demonstrated incremental value** (≈2,500 games each). Strict all-input ridge/GBM were no better than the line (total: worse, MSE gain −0.70, 95% CI [−1.24, −0.20], Holm-adjusted p 0.11, season-block CI includes 0; spread: −0.31 [−1.04, 0.41]; winner log-loss gain −0.0006 [−0.0024, 0.0011]). Inputs tested: opponent-adjusted pass/rush EPA, success rate, pressure/sack matchups, explosive plays, scoring conversion, turnover regression, penalties, snap-share-weighted injuries by position group (timestamp-filtered), rest, pace, pass-rate-over-expected, QB quality/change (partial), weather (partial), market-level controls and 3–4 pre-specified interactions per family. Without any market the inputs do carry real information (strict+partial inputs explain ~5% of total-points and ~15% of margin variance out of sample) but the near-close line explains more (10% and 20%): the market already absorbs it.
* **NFL QB passing yards vs the QB's own shrunk historical rate (no market, L1):** the strict pregame model cuts out-of-sample MSE by 3.9% (gain 208 [144, 271], Holm p≈0.007, both halves and every leave-one-season-out positive, season-block 95% CI [147, 270]); adding the realised-QB and weather inputs raises that to ~5%. Groups demonstrated: game script (spread/total/implied team total), opponent pass defence, opponent pass-volume faced; environment (observed weather/roof) is also demonstrated but is partial-pregame. Suggestive only: opponent pass rush, team pass-offence quality, and one interaction (pressure matchup × QB sack-proneness, Holm p 0.04 but fails the stability gates; partial). Not demonstrated: injuries, other interactions. The game-script inputs come from near-close game lines, so this shows what a prop model should condition on, not that any prop price is mispriced. Sample caveat: QB1 (most dropbacks, ≥12) is itself realised, so early exits are excluded.
* **Weights:** reported ridge coefficients are descriptive (fit on all history, conditional on the other inputs, shrunk) and are shown on the dashboard **only** for inputs whose incremental test cleared the bar; otherwise the dashboard says "weight not reliable (no demonstrated effect)".

## Verification record (PR #53)

* Benchmark cross-check: my near-close total residual on 2020–2025 reproduces the existing repo study (`NFL_totals_incremental.json`) exactly (MAE 10.2833, RMSE 13.0422, n=1,615), and both find no incremental gain for football features on totals.
* Reproducibility: two full runs on the same cache give byte-identical artifacts (timestamps aside); a run from an **empty cache with a real download** (358 MB, 50 files) reproduced identical results even though `games.csv` differed by 3 bytes. Source files are the latest release assets (unpinned); per-file sha256 in `provenance.json` identifies the exact bytes.
* Leakage tests: rolling ratings cannot see their own game; walk-forward predictions cannot see later outcomes (corruption test); injuries use the final report with kickoff-timestamp filtering (25 of 85,337 report rows were stamped after kickoff and dropped; 8,570 rows have no timestamp and cannot be verified, so they are kept and counted) and the player's *prior* snap share via an as-of join; a planted-signal/noise test checks the verdict ladder.
* Dashboard: all 275 families, 672 inputs and 679 hypothesised interactions are present in the published data and tested as reachable (blueprint-level hypotheses are shown under a collapsible parent-blueprint panel; four catalog inputs that were initially unattached to any market were attached and the validator now rejects orphans).
* Playwright (existing 5 specs + 7 new dashboard specs): 28/28 pass on desktop Chromium and an iPhone-13-emulated Chromium here; the new `e2e.yml` workflow runs the same suite in CI on real desktop Chromium and iPhone WebKit. Two pre-existing e2e failures on `main` (ambiguous locators) were fixed test-side.

## What remains unproven (do not promote)

* Anything beating a **Kalshi** price after spread, fees and depth. No L3/L4 anywhere.
* Every non-NFL sport and 271 of 275 families: inventory + availability only.
* NFL props vs a market: historical prop lines are not available free; capture Kalshi quotes prospectively (the NFL tape in `nfl-edge-finder` is the intended source) and re-run `qb_passing` with the market as benchmark.
* Untested NFL inputs (no free pregame source): coverage shell/man-zone, time-to-throw, pass-block win rate, route/target-share, CB shadow assignments. FTN charting (2022+) and PFR advanced pressure (2018+) are reachable and are the next feature additions.
* Realised starting QB and observed weather are NOT treated as pregame-knowable: they are tagged `partial`, excluded from every headline model and reported only as a sensitivity. A forecast-weather archive and an announced-starter feed are the fix.
* The near-close line's timing is undocumented; a verdict against it says nothing about earlier horizons or Kalshi prices. Week-cluster and season-block bootstraps do not fully remove serial dependence from overlapping rolling ratings; ten seasons is a small number of independent blocks.
* Injury report timestamps: 10% of rows have none (kept, counted). Free-source licence terms are nflverse's and were not independently verified.
* Catalog quality: the 8 catalogs were drafted in an automated pass. Input-level mechanism/rationale text is substantive; per-market `why` strings are partly formulaic (share reported per sport on the dashboard, from 0% NHL to ~65% Tennis). Free-source names were not all probed for reachability (only nflverse was). NFL overtime/tie wording is generic and needs a rulebook check.
* Registry gaps found: `NFL_MISC_UNCLASSIFIED` and four MLB/NHL families have no blueprint (shown as unclassified, never hidden); `NFL/PLAYER_STAT` lumps QB/rush/receiving/TD props (the dashboard offers an archetype selector); `CBB/OTHER` has no blueprint.

## Method notes

* Leakage controls: team ratings are chronological, opponent-adjusted EWMAs updated only after each game (unit-tested: corrupting a game's outcome cannot change its own or earlier features); injuries use the final report plus the player's **prior** snap share via an as-of join (a regression test covers the Out-player-has-no-snap-row case); ridge penalty is chosen on the last training season only.
* Overfitting/false discovery: ~60 inputs × 20 groups × 6 interactions per family are tested; Holm over groups and interactions, BH q-values over single inputs, leave-one-season-out and both-halves stability. Reported as discovery leads (q) vs confirmatory verdicts (Holm).
* Weights are ridge coefficients per +1 SD (bootstrap CI) fit on all history (descriptive, not used for evaluation) plus GBM partial dependence and permutation importance.

## Follow-on: market-universe audit and the first Kalshi-priced experiment (L3 attempt)

**Market universe** (`alpha_engine/input_research/market_universe.py`, artifacts under `research/input_research/market_universe/`): the public `GET /series?category=Sports` listing (4,156 series, 2026-11-06) classified by ticker/tags and compared with every series ticker already present in `research/audit`. Series-level only: it shows which kinds of markets exist, not contract counts, open/settled split or settlement-rule review. Findings: NFL, CFB, MLB, NHL, NBA, CBB and tennis are almost fully known (0–3 new series each); **soccer has 1,144 of 1,546 listed series the registry has never seen** (leagues, totals, spreads, team events, player props), and 1,384 further series (1,139 of them also unregistered) belong to sports/leagues outside the eight (golf, motorsport, esports, MMA, cricket, women's/international basketball, other baseball/hockey leagues). Those are **unsupported**: no registry family, inputs or tests. Re-run: `python -m alpha_engine.input_research.market_universe` (fetches live) or pass a saved `series.json`.

**Experiment NFL-PASSYDS-1** (`alpha_engine/input_research/prop_experiment.py`, results `research/audit/input_research/experiments/nfl_passyds_kalshi_v1.json` + per-contract CSV): the **market-free** QB passing-yards model (selected by the nested search below on 2013–2025 only; spread from walk-forward OOS residuals; an earlier version used sportsbook-derived game-script inputs and was replaced, see Policy) priced against **authentic Kalshi KXNFLPASSYDS contracts** for the 2026 regular season (weeks 1–8), using hourly yes_bid/yes_ask candles from the public API and Kalshi's taker fee on a 10-lot. Design, horizons (T−60m primary; T−3h, T−24h secondary), 5¢ net-edge rule, game-clustered bootstrap and the eligibility limitation are pre-registered in the module docstring. One post-hoc fix is disclosed: the first run mis-parsed two-letter team codes (GB, TB, KC, NE, NO, SF, LV) and silently dropped those games; this was found by inspecting the exclusion bucket, fixed, tested (`TeamSplit`) and re-run; no model, threshold or horizon was changed.

Reproduce (free): download the nflverse cache as in the refresh above, then `python -m alpha_engine.input_research.prop_experiment --data-dir <cache> --cache-dir <scratch>`; the Kalshi markets/candles are fetched and cached in `<scratch>`.

**Read the result as:** no demonstrated edge, and a known bias. Fills are hypothetical (top of book, depth unobserved). Eligibility requires the realised QB1 (≥12 dropbacks), which is unknown at quote time; contracts on players who did not meet that bar are excluded and resolved YES far less often, so the model-eligible subset is flattered (realised YES exceeds the market mid by ~2.5 points there, versus −21 points on the excluded). The fix is prospective capture of the announced starter, not a better backtest.

**Experiment NFL-GAME-1** (`game_experiment.py`, `nfl_game_kalshi_v1.json`): does the Kalshi KXNFLGAME winner price lag the de-vigged sportsbook moneyline? 242 settled contracts / 121 games of 2026 weeks 1–8, all with a two-sided quote at T−60 min. Kalshi's mid averages 0.05¢ from the book; no contract clears a 3¢ fee-adjusted edge at T−60 min; the two T−24 h qualifiers come from one game. No cross-market mispricing; caveat: the book line is "near close" and may post-date the quote.
**Model-free structural test** (in `nfl_passyds_kalshi_v1.json`, `structure_test_primary_T-60m`): all 2,130 two-sided KXNFLPASSYDS contracts × 8 price bins × side, taker fees, 16 cells, Holm over all 16, exact H0 simulation, minimum 30 contracts / 10 games. 0 cells pass; the one nominal outlier (YES at 0.9–1.0, 23/23 wins) has a degenerate bootstrap interval and an exact p of 0.16.

**Catalog editorial pass (started):** 46 formulaic Tennis rationale strings (match winner, total games/sets, set/game spreads: the three highest-ranked Tennis archetypes) were rewritten with the mechanism by which each input moves that contract; Tennis formulaic share 63.8% → 52.3%. ~8 other Tennis archetypes and the other seven sports still carry formulaic text (published per sport on the dashboard); this is a hypothesis review, not new evidence.

**Slow-incorporation test** (`drift_test`, same artifact): KXNFLPASSYDS mids move little before kickoff (median |T−24h→T−3h move| 1¢, 99th percentile 5¢); only 23 contracts / 13 games moved ≥ 5¢, below the pre-set minimum, so "markets absorb news slowly" is **untestable on this history** (not rejected). Prospective capture of the quote path around injury/inactive announcements is the way to test it.


## Policy correction and P0–P3 foundation (2026-11-06)

**Primary models are market-free.** No sportsbook line, Kalshi price or feature derived from them may enter a primary prediction model; they are benchmark-only, used after a model is fixed to look for mispricing. `alpha_engine/input_research/marketfree.py` enforces this in code (`assert_market_free` raises on `spread_line`, `total_line`, moneyline/odds/price/bid/ask/implied-total columns and derived interactions) and supplies the model's OWN game-script expectation (`own_script`: walk-forward ridge on opponent-adjusted ratings, correlation with the outcome 0.375 margin / 0.213 total vs 0.447 / 0.314 for the market lines). **Legacy exceptions, now flagged:** the #53 QB passing-yards L1 study and the NFL total/spread/winner L2 studies include line-derived inputs (game script, "market-structure controls"); the L2 studies are *benchmark-residual tests* (does anything add to the line), not independent predictors, and the L1 study is superseded by the market-free search for any probability used against Kalshi.

**P0/P1 audit** (`coverage_audit.py`, `coverage_audit.json`): for every archetype, which mechanism categories its market kind requires but its inputs (including the parent blueprint's) lack (86 of 118 archetypes show at least one, mostly game-state, pace/volume and matchup: a review checklist, not proof of insufficiency); which of the 672 inputs are price-derived and therefore benchmark-only (7–10 per sport, e.g. external lines, quote history, order-book depth, trade tape, ladder structure, fees, market-implied ratings); and per sport how many model-eligible inputs are collected with point-in-time archiving, partial, missing (source exists / no free source) or unverified. Source reachability: 0 of 80 free-source hosts were reachable from the research runner (its network policy blocks them; this says nothing about the sources). The environment allowlist was extended with six free public hosts (MLB StatsAPI, NHL API, NBA CDN, ESPN API, football-data.co.uk, tennis-data.co.uk); nflverse and Kalshi were already reachable, Sackmann's tennis repositories are not attachable to this session. Re-run `python -m alpha_engine.input_research.coverage_audit --probe` next session; non-NFL data pulls are the next P1 step.

**P2 search engine** (`search.py`, `search_nfl_qb.py`; tests `tests/test_search_and_audit.py`): per outer season, random search (seeded) over input-group subsets, optional squared terms, 0/6/20 data-picked pairwise interactions, ridge penalty or shallow boosting; scored on inner chronological folds (train before V, validate on V, last 3 seasons before S); one-standard-error simplest-wins selection; refit and predict S. The permutation null (residual shuffled within season, identical procedure) measures the search's own overfitting. Harness is table-in/table-out so other sports plug in once their data exists. NFL QB passing yards (market-free, 200 configurations per fold, outer seasons 2019–2025, 3,721 QB games): **MSE gain 1.94% vs the QB's own history** (bootstrap CI excludes 0; 6 of 7 seasons positive); permutation null +0.29% / +0.17%. Boosting was never selected (ridge in 7/7 folds). Leave-one-group-out importance (inner folds, fixed structure): only opponent pass defence helps in all 7 folds; environment and own game script are borderline; the other groups are not consistently needed. No weights promoted.

**P3 against Kalshi** (same artifact as NFL-PASSYDS-1, now with the market-free primary model): T−60m, 2,036 priced contracts / 122 games. Log-loss: model 0.503, history-only 0.503, fixed ridge 0.506, **market mid 0.488**; model minus market gain −0.015 [−0.028, −0.001] (the market is better and the interval excludes 0). 440 qualifying trades (≥5¢ net edge): −5.5¢ [−12.7, +2.4]; YES side +4.0¢ (n=200), NO side −13.5¢ (n=240); all hypothetical fills and eligibility-biased toward YES. Conclusion: independent probabilities of this quality do not identify mispriced Kalshi passing-yards contracts; better inputs (target share, routes, coverage) and an announced-starter capture are required before the comparison is worth repeating.
