Columns used: tourney_id, tourney_name, tourney_date, best_of, match_num, winner_id, loser_id, score. Use only pandas/numpy. Do NOT read anything under /home/user or any repository clone. ## Universe and keys
Read every file (sorted names, rows in file order), tour = file-name prefix. Drop rows with null tourney_date, winner_id or loser_id. date = tourney_date as YYYYMMDD (tournament START date). game_id = `"{tour}|{tourney_id}|{match_num}|{k}"` (match_num as integer; k = number of EARLIER rows (read order) with the same `"{tour}|{tourney_id}|{match_num}"` string). Player key `"{tour}:{id}"`. Output two rows per match: (game_id, winner key) and (game_id, loser key); both rows carry identical values.
## Score parsing
Blank/non-text score -> unusable; contains 'W/O' -> unusable; flag RET if it contains 'RET', else DEF if 'DEF', else unusable if it contains 'ABD' or 'UNP'. Tokens = whitespace-split pieces other than RET, DEF, ABD, UNP; each must match `^(\d+)-(\d+)(\(\d+\))?$` (first number = winner's games) else unusable. complete_set(a,b) = (max>=6 and max-min>=2) or (max==7 and min in (5,6)). A match is OK only if it has no RET/DEF flag, is usable, need = best_of//2+1, ws = #tokens with a>b, ls = #tokens with b>a, max(ws,ls) == need and every token is complete (a missing best_of makes it not OK). For OK matches: tb = 1 if any token has max == 7 and min == 6 else 0; straight = 1 if ls == 0 else 0.
## ten.tiebreak_base_rate_by_event -> tbe_tb_rate_pre, tbe_ss_rate_pre, tbe_n_eff_pre
Values (OK matches only; NaN for the rest): tb and straight. For a match with date d use only matches with date STRICTLY EARLIER than d and date >= d - 1095 days. EVENT key = (tour, tourney_name): each such earlier match m of the same event weighs w = 0.5 ** ((d - d_m in days)/548); ne = sum of w over matches with a non-NaN value of the column, er = sum(w*value)/ne. TOUR rate tr = plain mean of the column over earlier matches (same window) with key (tour, best_of) (NaN if none). Value = (ne*er + 60*tr)/(ne + 60) if ne > 0 else tr. tbe_tb_rate_pre uses the tb column, tbe_ss_rate_pre uses straight; tbe_n_eff_pre = ne of the tb column (0 if no earlier event match).
NUMERICAL REQUIREMENT: results are compared to 1e-9 relative. Compute the weights directly per (match, earlier event match) pair as `0.5 ** (days/548)` and sum them with float64; do NOT use cumulative-sum differencing across keys or any 2**(large) rescaling trick (those lose ~1e-7 precision).
